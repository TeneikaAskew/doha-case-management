# DOHA Case Management

Personnel-vetting case management demo. React portal in `portal/` (Vite + react-router,
plain CSS variables), deterministic demo data generated by `portal/data_gen/` (Python +
pydantic) into `portal/public/data/`.

## Writing style (UI copy, generated data, docs, comments)

- Never use em dashes (—) or en dashes (–). Use a plain hyphen (-) instead, or rewrite
  the sentence. This applies to UI strings, generated demo data, tests, comments, and docs.
- Avoid AI-idiom phrasing in copy: no "delve", "leverage", "seamless", "robust",
  "comprehensive", "it's worth noting", "in the world of", or similar filler. Write
  plainly and specifically.
- Headers, card titles, KPI labels, nav items, and stage/status labels use Title Case
  ("Continuous Vetting", "Initial Vetting Backlog", "Open Alerts"). Body text, buttons,
  and form labels use sentence case.
- Alert workflow states render as neutral gray badges (`ALERT_STATE_VARIANTS` in
  `portal/src/domain.js`); semantic colors are reserved for severity, status, and risk.

## Data rules

- All identities are fictional: 900-series SSNs only, 555-01xx phones, example-domain
  emails. Every subject profile must be fully populated (see
  `data_gen/tests/test_generator.py::test_every_subject_profile_is_complete`).
- Data is deterministic: fixed `TODAY` in `hero_cases.py`, no randomness.
- After editing `data_gen/`, regenerate: `cd portal/data_gen && python generate_demo_data.py`
  and commit the regenerated `portal/public/data/` alongside.
- Provider names on record checks and documents must exactly match `providers.json`
  names (UI alias map in `SourceChip.jsx` covers legacy alert strings).

## Commands

- Portal tests: `cd portal && npx vitest run`
- Data tests: `cd portal/data_gen && python -m pytest tests -q`
- E2E smoke: `cd portal && npx playwright test`
- Dev server: `cd portal && npm run dev` (HashRouter: routes are `/#/...`)
